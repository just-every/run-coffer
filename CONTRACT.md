# Coffer first-release contract

These clauses describe the behaviour the code enforces. Tests in `tests/coffer.test.mjs` exercise them through the Worker's HTTP doors.

- **HTTP-001 — Private app boundary.** Hono serves `/health` and owns `/api`; native owner/operator sessions protect `/app` and `/api/coffer`. Every handler checks the actor's role, the exact host and, for cookie changes, the same `Origin`. Each write batch re-checks the session or key inside the same D1 transaction, so a revoked session, role change or revoked key stops a request in flight. Unknown paths return real 404s.
- **DONOR-001 — Donors and households.** A donor has one unique email (or none). A household is found by name or created. Members, admins and the owner add and edit donors; edits are versioned.
- **GIFT-001 — Immutable ledger.** A gift is an integer-cent line with its date, method, fund, optional pledge and goods-or-services answer. Database triggers refuse changes to amounts, dates, donors or references; a correction is a reversal line of the opposite amount, once per gift. Dollar input is parsed exactly; the API takes `<field>Cents` for exact integers.
- **CONSENT-001 — Consent history.** Consent is append-only per donor and channel (email, postal mail) with method, evidence, capture date and who recorded it; the newest row is the current answer. Rows are removed only by erasure.
- **ACK-001 — Acknowledgement letters.** Gifts at or over the threshold (default $250) without a live letter are due within the target days (default 14). No letter is prepared until a person has saved the settings; the letter must state donor name, amount, gift date, organization and the goods-or-services statement. A batch freezes its letters and content hash. A person approves the exact hash; export, then a recorded sent date. Coffer never sends mail. Imported gifts with an unknown goods answer wait for a person's answer.
- **APPEAL-001 — Consent-checked appeals.** An audience includes only donors whose newest consent for the channel is yes and who have the needed address; exclusions are counted by reason. Each recipient is frozen with the exact consent row; approval and export refuse if any of those rows is no longer current.
- **AGENT-001 — Prepare, then a person decides.** An expiring, revocable bearer key reads records and runs only `ack.prepare` and `appeal.prepare`. Approvals keep the preparer's and approver's identity and role with the content hash.
- **IMPORT-001 — Reviewed Stripe move-in.** Saved Stripe customer and charge list pages go through Base's import kit. Preview writes nothing; apply needs the exact reviewed fingerprint; the journal retains the original pages; undo stops at anything a person has since built on. Failed, refunded, non-USD, duplicate and already-imported objects are skipped with reasons and never enter the plan.
- **DATA-001 — Custody and erasure.** Base portability backs up product records, approvals and import custody, excluding identity and credentials, and restores only into an empty installation. The owner erases a donor with explicit `ERASE`: personal data, consent, letter text, gift notes and affected Stripe originals go; gifts move to an anonymous placeholder; hashed suppression stops re-import; a later journal fences older archives.

Release one excludes payments, sending, grants, wealth screening, tax advice, non-cash gifts and a live processor connection.
