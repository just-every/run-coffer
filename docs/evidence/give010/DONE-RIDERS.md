# Before you claim DONE: what ct's judges look for (26 Oct 2026)

Derived from the 26 October STAYS PARTIAL and demotion rulings (Nectar DUN-004, Beam LEARN-008, Terrace PAY-013, Plinth BILL-005 and DOC-005, Willow SIGN-001 and SIGN-002, Strap RPT-004, Pane, Uptime PERF-001). A DONE is accepted only when none of these applies. Check each against the exact candidate SHA before you post a claim.

| # | Recurring reason a claim stays PARTIAL or is demoted | Proof that satisfies it |
|---|---|---|
| 1 | An acceptance sentence no test asserts. The journey runs and passes, but zeroing the rate, dropping the row or returning an empty list would still pass (Nectar recovery rates; Terrace ACH across two households; Strap exclusion cases). | For every sentence and rider, name the tagged test and line that asserts the exact value or refusal. Run one mutation per sentence (zero it, omit it, widen it) and show the named assertion fails. |
| 2 | Vacuous or one-sided assertions: loops over a possibly empty list, expected values computed from the same input, only positive fixtures or only negative ones (Envelope PA contact name; Beam lexical veto refusing ordinary paraphrases). | Assert the expected set explicitly, derive expected values independently, and cover both directions: the supported case is served and the unsafe case is refused. |
| 3 | Proof not loaded in a recorded run on the exact SHA: browser screens at 1440 and 390 behind an env flag or nightly only, journeys outside Verify, a heavy-slot receipt for an earlier commit. | The journey is invoked by push, pull_request or dispatch Verify and that run is green on the candidate SHA. An outside-Verify job counts only where the sentence names a clock or scale proof, with its receipt at the exact SHA. |
| 4 | Evidence from an earlier SHA: mutation receipt, provider test run or screens recorded before the last code change (Beam 8f6fa55e, Strap Stripe TEST b3649079, Nectar 8e3806da). | Re-run on the candidate, or show with a diff that no byte of the relevant code or test changed since. |
| 5 | Inheritance claimed but not written: the receiving clause does not name the duty in both documents. | Add the duty to the receiving clause in CONTRACT.md and ACCEPTANCE.md (pattern 1) or keep it in the Gap of the clause that owes it. |
| 6 | Gap, Evidence or provenance stale: Gap not empty on a DONE row, still lists proofs now present, or omits proofs still missing; footers and "judged at commit" lines name an old SHA; counts differ between CONTRACT.md and ACCEPTANCE.md; a clause DONE in one document and PARTIAL in the other (CAT-004). | One recount of raw Status rows in both documents, equal id for id; a Gap that is empty or names only carved clauses; provenance lines at the candidate SHA. |
| 7 | Original acceptance sentences or CT rider paragraphs reworded, shortened or not byte-identical in both documents. | Keep every original sentence verbatim; paste CT riders exactly; diff the two documents for the clause. |
| 8 | Permission and authority holes: a correction or refund verb resolves to a weaker permission, a non-owner or paid-invoice path is unasserted (Plinth BILL-005). | Assert refusal for the non-owner, wrong-state and wrong-permission cases through the public door, and audit, archive and closed-period behavior for each verb. |
| 9 | A provider or legal boundary reported as proven: retention, deletion, settlement, DocuSign, native devices, tax or compliance. | Keep the honest boundary named in the Gap; claim only what a real provider receipt or journey shows at the exact SHA. |
| 10 | Policy default adopted without ruling: custody, consent, spending or authority choices shipped and counted before ct approved them. | Post an ASK with the default first; count nothing until the ruling, then synchronize its exact wording. |
| 11 | Landing conditions not met when counted. | Main equals the SHA (ls-remote); exact-SHA Verify green (a canceled duplicate main-push Verify is not counted); Run site green on it; complete full-history publication scan NEW 0; diff against the prior main limited to the clause's status, Gap and counts plus the work. |

Judge request format that avoids a round trip: the exact SHA, run ids with their event, the clause list, and for each sentence the test and line that asserts it and the mutation that fails it. Claim DONE only when you would sign every row above yourself; ct runs one fresh judge per DONE claim and counts nothing until it rules.
